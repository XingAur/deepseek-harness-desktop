# DeepSeek Harness Desktop 长期产品与开发路线图

**制定日期：** 2026-08-24

**当前桌面版本：** 0.1.19

**目标用户：** 希望安装后直接使用 AI 编程能力的普通 Windows 用户，同时为高级开发者保留受治理的扩展空间

**实施原则：** 可靠性优先、小白主流程优先、安全默认开启、复杂能力渐进暴露、每个可验收步骤独立提交

## 1. 产品目标

DeepSeek Harness Desktop 的长期目标不是简单包装官方 Web UI，而是把 Runtime、模型配置、项目、会话、更新、诊断和本机权限整合成普通用户可以理解和信任的桌面产品。

用户应当可以完成以下闭环：

```text
下载安装包
  → 首次启动自动准备受管 Runtime
  → 配置模型供应商和 API Key
  → 创建或选择本地/远程项目
  → 发送第一条消息并实时看到回复
  → 安全运行、恢复和升级
  → 在桌面端或移动伴侣中继续任务
```

## 2. 已确认的产品边界

### 2.1 当前坚持的方向

- Windows 优先，完整安装包优先。
- Runtime 是受管组件，用户不需要自己安装 Node、pnpm 或 DSH。
- 兼容 Runtime 快速启动；不兼容时可见地升级并支持 last-known-good 回滚。
- Profile、Workspace、Session 和 Runtime 生命周期由官方能力与桌面协调器共同管理。
- 普通用户默认只看到模型、项目和对话，高级能力放在设置或独立入口。
- 关键状态由官方事件与持久化投影驱动，不由临时前端对象猜测。
- 凭证不进入仓库、日志、诊断包或普通前端持久化。

### 2.2 当前明确不做

- 不恢复在线小安装器作为主发行形态。
- 不恢复社区插件市场或插件核心导航。
- 不允许任意远程代码安装后直接获得桌面 IPC。
- 不把完整 Runtime 暴露到公网供移动端直接访问。
- 不在缺少评测证据时默认开启自动任务路由。
- 不为了未来可能出现的 Runtime 提前进行大规模抽象重构。

## 3. 当前实现基线

仓库已经具备以下基础能力，后续以加固和真实验证为主，不重复从零建设：

- Generation 生命周期和候选激活。
- Profile pending / last-known-good 恢复。
- Windows 与 macOS Platform Adapter。
- Runtime 签名清单、版本化安装、健康检查、回滚和快速启动。
- Windows 应用更新签名与 macOS 手动 DMG 更新路径。
- 固定用户数据目录、迁移、诊断导出和受限安全导航。
- 原生托盘、受管进程树和隐藏 Windows 辅助命令窗口。
- 本地项目卡片、重命名、内置封面、置顶、删除确认和回收站处理。
- 本地应用启动器和受管静态服务。
- 自动上游同步、Release 草稿、不可变资产校验和双平台构建工作流。
- 单元测试、Rust 测试、Web/插件构建、确定性模型夹具和部分安装包 E2E。

当前最重要的剩余风险不是“缺少功能”，而是会话实时一致性、安装包真实闭环、Runtime 契约漂移和首次使用门槛。

## 4. 总体优先级

| 优先级 | 阶段 | 目标 | 发布意义 |
| --- | --- | --- | --- |
| P0 | 可用与可信 | 会话一致性、完整安装 E2E、Runtime 契约门禁、Bridge 版本化 | 阻断有缺陷版本发布 |
| P1 | 小白开箱即用 | 模型引导、第一次成功对话、错误自愈、普通用户文案 | 降低首次使用失败率 |
| P2 | 日常体验 | 会话管理、本地用量统计、性能、无障碍、安全皮肤 | 提高留存与可理解性 |
| P3 | 受治理扩展 | Agent Adapter、Provider、MCP/Skills、工作台扩展、SSH | 支持高级场景而不污染主流程 |
| P4 | 远程与智能化 | 自动路由实验、移动伴侣、可选扩展目录 | 扩展使用场景 |
| P5 | 生态与规模化 | 生态收录、兼容计划、发布证据和贡献者机制 | 扩大影响力与维护能力 |

阶段按出口条件推进，不以固定日期强行切换。P0 未通过前，不投入 P3、P4 的大规模实现。

## 5. P0：可用与可信

### P0.1 官方 Session Event 单一事实源

**目标：** 新建、发送、回复、标题更新和会话切换全程无需刷新。

**实施内容：**

1. 以官方 Session Store 和 `session/event` 投影作为标题、消息、运行状态和当前会话的唯一权威。
2. 删除 `project-controller.ts` 中 `waitForSessionBinding` 轮询。
3. 固定会话建立顺序：`create/connect → binding → open → prompt`。
4. binding 不符合上游同步契约时立即返回可诊断错误，不用轮询掩盖契约破坏。
5. 页面不维护第二份临时会话内容，不通过刷新重新拉取来补偿事件丢失。
6. 会话切换取消旧会话的 UI 订阅，但不取消仍在 Runtime 中运行的任务。

**测试门禁：**

- 单元测试验证准确调用顺序。
- 两个会话之间连续切换 20 次，标题和消息始终对应。
- 发送首条消息后，用户消息在本地可观察阈值内出现。
- 确定性回复完成后标题更新，无需刷新。
- 重启应用后会话和标题仍可见。
- WebSocket 断开后显示重连状态；恢复后补齐事件，不创建重复会话。

**出口条件：** 安装版连续完成 30 轮创建和切换，无空白会话、重复会话和刷新依赖。

### P0.2 Windows 完整安装生命周期 E2E

**目标：** 用真实安装产物发现单元测试无法覆盖的缺文件、锁、路径、升级和卸载问题。

**测试分层：**

#### 每个 Pull Request

```text
构建候选应用
→ 启动确定性 Runtime
→ 创建 Unicode 路径项目
→ 发送消息
→ 标题与回复实时出现
→ 创建第二个会话并切换
→ 退出并再次启动
→ 会话仍可见
```

#### 每日或 Release Candidate

```text
静默安装
→ 首次启动
→ 内置 Runtime 准备
→ 工作台加载
→ 创建项目并对话
→ 退出重启
→ 覆盖升级安装
→ Profile、项目和会话保留
→ 卸载并验证用户选择
```

#### 手动 `workflow_dispatch`

- 使用 GitHub Secret 中的真实 DeepSeek API Key。
- 只发送固定、无敏感信息的测试问题。
- 验证真实流式回复、取消和重试。
- 不上传包含 Key、认证头、用户路径或完整回复的日志和截图。
- 真实 API 失败不阻断普通 PR，但阻断正式发布人工确认。

**出口条件：** Release 页面只接受通过安装、首次使用、重启、升级和卸载证据的 Windows 资产。

### P0.3 Runtime 激活前兼容性门禁

**目标：** 防止新版 Runtime 可以启动但 Workspace、Session、Profile 或插件局部失效。

候选 Runtime 激活前必须验证：

- 健康接口、Runtime 版本、Profile ID 和配置修订。
- `/api/events.mux` 与 `/api/events.host` WebSocket 握手和事件接收。
- Workspace list/create/connect 契约。
- Session create/binding/open/prompt/cancel 契约。
- Desktop 插件加载和关键 Slot 注册。
- 桌面 Bridge 协议版本与能力集合。
- 候选进程稳定窗口和受管进程树身份。

任何检查失败都不得推进 active pointer，必须保留 last-known-good，并输出明确的失败阶段和可导出诊断。

### P0.4 Desktop Bridge 与 Host Contract 版本化

**目标：** 将桌面原生能力与 Runtime/Web UI 的边界变成可验证的公共契约。

每个 Bridge 请求包含：

- `protocolVersion`；
- `requestId`；
- `generationId`；
- `capability`；
- 类型化 payload。

每个响应包含成功结果或稳定错误类别。父窗口只接受当前 iframe、当前受管 origin 和当前 Generation 的请求。替换 Generation 后旧请求立即失效。

公开 Contract 必须有版本兼容矩阵和 fixture 测试；不提供通用 shell、任意路径文件系统或任意进程能力。

## 6. P1：小白用户开箱即用

### P1.1 首次启动模型配置引导

**用户流程：**

```text
选择供应商
→ 输入 API Key
→ 测试连接
→ 自动读取模型目录
→ 推荐默认模型
→ 进入工作台
```

第一步先验证固定 DSH Runtime 是否稳定暴露 Settings、Credentials、Provider Route 和模型目录接口。无法通过稳定 Contract 完成的供应商不进入首批引导。

首批优先 DeepSeek；其他 Provider 按官方契约、凭证安全和维护成本逐个评估。高级模型 ID、路由和推理参数默认隐藏。

**安全要求：**

- Key 只写 Harness Credential Store 或操作系统安全存储。
- 前端只接触短生命周期输入，不写 localStorage。
- 日志、诊断、错误提示和崩溃报告全部脱敏。
- 支持跳过配置和稍后完成。
- 连接测试使用短超时、明确错误分类和有限重试。

### P1.2 第一次成功对话闭环

产品成功指标从“安装成功”调整为“用户完成第一次有效回复”。

桌面端记录不含敏感内容的阶段耗时：壳层渲染、Runtime 就绪、模型验证、项目创建、首个 Session、首个事件和首个回复。失败界面只给普通用户一个主操作，同时保留导出诊断入口。

### P1.3 自愈与错误表达

- 网络问题、密钥问题、Runtime 问题、项目权限问题分别表达。
- 自动操作必须显示当前阶段和结果，不用无限进度条。
- 可恢复错误提供重试；契约或签名错误停止自动重试。
- 连续启动失败触发熔断，启动 last-known-good 或进入修复页。
- 诊断包默认脱敏，并让用户看到保存位置和包含内容。

## 7. P2：日常体验与可观察性

### P2.1 会话管理

- 搜索、重命名、归档和最近会话。
- 会话运行、等待、失败、取消和恢复状态。
- 会话时间线和关键工具执行摘要。
- 重复空会话只在证据充分时提供批量清理建议，不自动删除有效记录。
- 项目与会话保持官方 Workspace/Session ID，不建立第二套身份系统。

### P2.2 本地使用统计

- Token、调用次数、首 token 延迟、总耗时、缓存命中和失败率。
- 按项目、Profile、模型和日期查看。
- 成本必须基于用户确认的价格配置，不虚构官方价格。
- 默认只保存在本机；支持导出和清空。
- 不记录提示词、回复正文、Key 和工具敏感参数。

### P2.3 性能目标

- 本地启动页可感知渲染：参考机器不高于 1.5 秒。
- 兼容 Runtime 温启动进入工作台：参考机器不高于 8 秒。
- 不在温启动激活前访问更新网络。
- 大型会话采用虚拟化或分页，避免整个历史阻塞渲染。
- 每个启动阶段单独计时，便于定位退化来源。

### P2.4 安全皮肤系统

支持官方浅色、深色、跟随系统、若干内置配色，以及字号、密度、圆角、代码字体和动效偏好。

主题只允许声明式 Design Token：颜色、字体、间距、圆角、阴影和动效参数。禁止任意 CSS、JavaScript、远程字体和远程资源。主题文件包含 schema 版本、兼容范围和字段白名单。

必须覆盖高对比度、键盘焦点、缩放和 `prefers-reduced-motion`。

## 8. P3：受治理扩展与远程工作区

### P3.1 AgentRuntimeAdapter

在不改变 DSH 作为主要 Runtime 的前提下，先固定最小状态词汇：

```text
starting / ready / streaming / waiting / cancelled / failed
```

Adapter 覆盖能力发现、会话创建、恢复、取消、重试、结构化事件、错误分类和用量回传。只有第二种真实 Provider 或 Runtime 接入时，才验证并扩展抽象，避免为了假设场景重写现有 UI。

### P3.2 Provider、MCP 与 Skills 治理

- 配置、启用状态和权限按 Profile 隔离。
- 凭证使用安全引用，不进入扩展配置正文。
- 网络主机、工作区读写、任意文件、子进程、剪贴板和外部应用分别授权。
- 支持单次允许、持续允许、拒绝和撤销。
- 扩展失败只影响自身，不能拖垮桌面壳和主会话。
- 记录不含敏感正文的调用来源、能力、结果和失败类别。

### P3.3 工作台扩展

首批只开放有限 Slot：

- 左侧辅助面板；
- 右侧详情面板；
- 会话工具栏动作；
- 项目卡片动作；
- Git、任务看板、文件预览和结构化产物查看器。

扩展必须声明 Slot、Contract 版本、Runtime 兼容范围、权限、来源、签名和完整性哈希。Renderer 扩展不能直接调用 Tauri IPC，只能通过版本化 Bridge 使用批准能力。

工作台扩展属于高级设置，不恢复插件市场，也不出现在小白主导航中。

### P3.4 SSH 远程工作区

**产品形态：** 用户配置 SSH 主机并选择远程目录，桌面端通过受控隧道连接或启动远程 Harness Runtime，本地继续展示统一工作台。

**实施顺序：**

1. SSH 主机配置和连接测试。
2. 系统 SSH Agent、密钥引用和安全存储。
3. `known_hosts` 主机指纹确认与变化阻断。
4. 远程目录选择和工作区范围授权。
5. 远程 Runtime 健康检查与版本兼容。
6. 受控 SSH 隧道和 Session Event 传输。
7. 远程项目卡片、断线状态和重连。
8. 远程任务取消、进程清理和跨平台 E2E。

不自动接受未知主机，不复制用户私钥，不把 Runtime 端口暴露到公网，不默认授权整台服务器文件系统。

## 9. P4：远程伴侣与智能化实验

### P4.1 自动任务路由实验

借鉴任务分类和两阶段工具开放的评测方法，但不复制依赖首轮临时 Session 状态的实现。

上线前必须完成：

- 离线任务集和固定基线；
- 规划优先与执行优先对比；
- 首次有效工具调用质量评估；
- 安全、延迟、成本和失败率评估；
- 灰度开关和快速回退。

普通用户最终只看到“自动模式”，人工覆盖放在高级设置。没有显著收益时不默认开启。

### P4.2 移动伴侣

移动端定位为桌面任务伴侣，不在手机上运行完整 Runtime。

首批能力：

- 查看项目和会话状态；
- 接收任务完成、失败和权限请求通知；
- 查看回复与执行摘要；
- 暂停、取消、批准或拒绝操作；
- 发送补充消息；
- 查看简化改动摘要。

连接采用设备身份、二维码配对、端到端加密、短期令牌和可撤销设备授权。手机不直接扫描局域网或访问公开 Runtime 端口。

第一阶段不做完整代码编辑器、任意终端、完整文件系统和本地 Runtime。

### P4.3 可选扩展目录

只先定义治理元数据：名称、版本、来源、兼容 Runtime、验证状态、权限、最后验证时间和完整性哈希。

只有签名、兼容测试、权限确认、故障隔离和回滚全部成熟后，才评估可信来源目录。该目录始终是可选高级模块，不重新占用核心导航。

## 10. P5：生态与规模化

- 提交高质量 Awesome 列表和生态索引。
- 为每个正式版本提供安装、升级、回滚和兼容性证据。
- 建立公开的 Runtime/Contract 兼容矩阵。
- 提供安全模型、数据目录、卸载行为和隐私说明。
- 建立扩展审核、漏洞报告和撤回流程。
- 为外部贡献者提供最小开发环境、确定性 fixture 和贡献指南。

推广不能早于产品稳定性；不使用无法复现的生态总量或活跃用户数据作为产品事实。

## 11. 测试与发布门禁

### 11.1 测试层级

1. 纯函数和状态机单元测试。
2. Rust 服务和受限系统集成测试。
3. Desktop 插件契约和组件测试。
4. Runtime 组装、签名与协议 fixture。
5. 打包候选 WebDriver E2E。
6. Windows 安装、升级和卸载 E2E。
7. 手动真实 API 和真实机器验收。

### 11.2 正式发布最低条件

- `npm run check` 通过。
- `cargo test --locked` 通过。
- Runtime/Bridge 兼容测试通过。
- Windows 安装生命周期 E2E 通过。
- Release 资产签名、哈希和版本一致。
- 升级不丢失 Profile、项目和会话。
- 诊断与日志敏感信息扫描通过。
- 没有已知的刷新依赖、启动失败、卸载卡死或数据破坏缺陷。

macOS 未使用 Apple Developer ID 签名和公证时，Release 必须继续明确提示这一限制，不能把本地构建成功描述为完整发行验证。

## 12. 指标与验收

### 12.1 核心产品指标

- 安装成功率。
- 首次 Runtime 就绪率与耗时。
- 模型连接测试成功率。
- 首次有效回复完成率与耗时。
- 会话空白、重复和刷新依赖发生率。
- Runtime 更新成功率和回滚率。
- 应用升级后的数据保留率。
- 崩溃循环和手动修复触发率。

这些指标默认保存在本机；任何匿名遥测都需要单独设计、显式说明和用户同意。

### 12.2 阶段推进规则

- P0 出口条件全部满足后，P1 才能成为主开发线。
- P1 首次成功闭环稳定后，才能扩大 Provider 数量。
- P2 统计和皮肤不能修改官方 Session 权威状态。
- P3 扩展必须先通过权限、隔离和回滚测试。
- P4 移动端必须复用已经验证的远程事件与设备授权协议。
- 任一阶段发现数据破坏、安全绕过或发布阻断问题，立即回到 P0 处理。

## 13. 实施与提交规则

长期路线图拆成独立子项目，每个子项目都执行：

```text
事实核对
→ 设计规格
→ 用户确认
→ 失败测试
→ 最小实现
→ 验证
→ 独立提交
→ 下一步
```

每个可验收步骤单独提交，提交信息使用中文 Conventional Commit，例如：

```text
test(session): 增加新会话实时投影回归测试
fix(session): 使用官方绑定契约打开新会话
test(e2e): 覆盖双会话无刷新切换
docs(roadmap): 更新 P0 会话一致性进度
```

提交不得包含 AI 对话、临时计划文件、密钥、诊断包、用户数据、构建缓存或无关工作树改动。每次提交前执行相关最小测试，阶段结束执行完整门禁。

## 14. 首个执行子项目

路线图批准后的首个实现任务为 **P0.1 官方 Session Event 单一事实源**：

1. 核对固定 Runtime 的 SessionRuntime create/connect 同步 binding 契约。
2. 为 `create → binding → open → prompt` 写失败测试。
3. 删除 `waitForSessionBinding` 轮询并实现严格 binding 检查。
4. 增加标题、消息和双会话切换的确定性 E2E。
5. 增加 Runtime 升级后的 Session Contract fixture。
6. 运行插件测试、Web 构建、Rust 测试和安装候选验证。

每一项完成并验证后独立提交。
